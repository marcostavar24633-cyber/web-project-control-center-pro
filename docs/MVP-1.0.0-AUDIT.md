# MVP 1.0.0 — статический аудит исходников

Дата проверки: 2026-11-15  
Источник: архив `web-project-control-center-mvp-1.0.0.zip` (34 файла, 45 991 байт).  
Метод: просмотр структуры, конфигурации и ключевых исходников. Полноценная установка зависимостей, сборка и runtime-тесты в этой проверке не выполнялись.

## Итог

MVP содержит полезную основу: React/Vite frontend, NestJS API, отдельный BullMQ Worker, PostgreSQL/Prisma, Redis и Playwright. Но переносить его в production без исправлений нельзя.

## Найденные блокирующие проблемы

### P0 — ошибка структуры API-контроллера

Файл: `apps/api/src/audits.controller.ts`

После метода `history()` на строке 56 закрывается класс `AuditsController`, однако методы `artifactRoot()`, `listArtifacts()` и `getArtifact()` идут ниже, вне класса. Это выглядит как синтаксическая ошибка TypeScript и должно быть исправлено до первой сборки.

**Действие:** вернуть методы внутрь класса, затем выполнить typecheck/build API.

### P0 — отсутствует аутентификация и авторизация API

В контроллерах проектов, аудитов и отчётов нет видимых guards/проверок пользователя. Эндпоинты позволяют читать проекты/аудиты и запускать задания без проверки роли или владельца.

**Риск:** при сетевой публикации API посторонний пользователь может получить доступ к данным и расходовать ресурсы Worker.

**Действие:** до сетевого/production-развёртывания добавить authentication, workspace/project membership, RBAC, rate limiting и аудит операций. До этого API должен оставаться локальным или закрытым сетевым контуром.

### P0 — SSRF-защита неполная для браузерных проверок

Worker проверяет исходный URL и DNS до запуска Playwright, но браузер при загрузке страницы самостоятельно запрашивает скрипты, изображения, iframe и другие ресурсы. Эти запросы могут обращаться к внутренним адресам независимо от первичной проверки URL. Проверка DNS перед запросом также не является полноценной защитой от DNS rebinding без сетевого egress-контроля.

**Действие:** изолировать browser worker, запретить доступ к private/link-local/loopback/metadata диапазонам на уровне сети, фильтровать каждый запрос браузера и redirects, контролировать DNS и egress. Не считать текущую проверку достаточной для production.

## Важные замечания P1

- `docker-compose.yml` публикует PostgreSQL и Redis на всех интерфейсах хоста без пароля Redis. Это допустимо только для локальной разработки; для сервера нужно закрыть порты от внешней сети и настроить аутентификацию/сетевую изоляцию.
- В `.env.example` и Compose указаны демонстрационные credentials. Они не являются production-секретами; реальные значения должны задаваться через secret manager/переменные окружения и не попадать в Git.
- Артефакты Worker хранятся в локальной файловой системе. Для нескольких Worker/API реплик нужен общий object storage или общий защищённый volume.
- Для нескольких реплик планировщика требуется distributed lock/atomic claim, иначе возможны дублирующие задания.
- Скрипты и README расходятся по версии pnpm: корневой `package.json` задаёт `pnpm@10.0.0`, а инструкция MVP указывает pnpm 9. Версию установки нужно унифицировать.
- Текущий quality score — эвристика, а не показатель соответствия стандарту безопасности или готовности к публикации.
